# AeroSpace & Sketchybar

## AeroSpace

[AeroSpace](https://nikitabobko.github.io/AeroSpace/) is an i3-like tiling window manager for macOS. Config is generated by Home Manager at `~/.config/aerospace/aerospace.toml` (source: `modules/home-manager/macos/aerospace-desktop/aerospace.nix`).

### Startup

AeroSpace is launched via a Home Manager `launchd` agent rather than its native `start-at-login`, which is pinned to `false`.

The reason is that `start-at-login` makes AeroSpace register itself as a macOS login item through `SMAppService`, and macOS stores the *bundle path it was launched from*. For a package from nixpkgs that is a `/nix/store` path containing the version hash, so the login item points at one specific build forever. The next `aerospace` update changes the store path, the registered one no longer exists, and AeroSpace silently stops starting at the next reboot — with no error anywhere. This actually happened on the 0.21.1 → 0.21.3 update.

The launchd agent avoids this because macOS records only the *plist path* in Login Items, not the program inside it:

```
~/Library/LaunchAgents/org.nix-community.home.aerospace.plist   <- registered, stable
  └─ ProgramArguments: /nix/store/<hash>-aerospace-<version>/…  <- rewritten on every switch
```

The plist lives at a fixed location and Home Manager regenerates its contents on every switch, so the store path can never go stale. `--config-path` points at the generated TOML in the store for the same reason: agent and config are built in the same generation and cannot drift apart.

**General rule for GUI apps in this repo:** anything from `home.packages` that should autostart needs a launchd agent. Its `~/Applications/Home Manager Apps/<App>.app` is a *symlink* into the store, and macOS resolves it to the store path when registering. Apps from `environment.systemPackages` may use their own login-item mechanism — `/Applications/Nix Apps/<App>.app` is a real directory, so that path stays stable across rebuilds (this is why Raycast needs no agent).

Note that disabling `start-at-login` does not delete an already-registered login item; macOS only marks it `disabled`. Such leftovers are inert and are pruned eventually. There is no way to remove them explicitly short of `sfltool resetbtm`, which resets background-item approvals system-wide and is not worth it.

On startup, AeroSpace launches sketchybar and JankyBorders via `after-startup-command`.

### Key bindings

| Key | Action |
|-----|--------|
| `Alt + Enter` | Open Alacritty |
| `Alt + h/j/k/l` | Focus window (left/down/up/right) |
| `Alt + Shift + h/j/k/l` | Move window |
| `Alt + 1–9, 0, -, =` | Switch to workspace 1–12 |
| `Alt + Shift + 1–9, 0, -, =` | Move window to workspace |
| `Alt + f` | Fullscreen |
| `Alt + /` | Toggle tiles layout (horizontal/vertical) |
| `Alt + ,` | Toggle accordion layout |
| `Alt + Shift + Space` | Toggle floating/tiling |
| `Alt + Tab` | Jump to previous workspace |
| `Ctrl + Alt + h/l` | Previous/next workspace (wrap) |
| `Alt + Shift + ;` | Enter service mode |
| `Alt + r` | Enter resize mode (then h/l to resize, Esc to exit) |

### Workspace → monitor assignment

Workspaces are pinned to monitors by name. Edit `[workspace-to-monitor-force-assignment]` in `aerospace.nix` to adjust.

## JankyBorders

[JankyBorders](https://github.com/FelixKratz/JankyBorders) draws a colored border around the focused window. Config is generated by Home Manager at `~/.config/borders/bordersrc` (source: `modules/home-manager/macos/aerospace-desktop/jankyborders.nix`).

Current settings: round corners, 6px width, active border `#0088CC`, inactive border `#414550`.

JankyBorders is launched by AeroSpace on startup via `after-startup-command`.

## Sketchybar

[Sketchybar](https://felixkratz.github.io/Sketchybar/) is the status bar. Config lives in `modules/home-manager/macos/aerospace-desktop/sketchybar_config/` and is copied to `~/.config/sketchybar` at build time.

### Fast reload (no rebuild needed)

```bash
rm -rf ~/.config/sketchybar && \
  cp -r ~/nix-darwin-config/modules/home-manager/macos/aerospace-desktop/sketchybar_config/. ~/.config/sketchybar/ && \
  sketchybar --reload
```

The next `darwin-rebuild switch` will overwrite `~/.config/sketchybar` with the nix-managed version.

### Workspace icons

Open windows are shown as app icons using `sketchybar-app-font` glyphs (via `__icon_map` in `plugins/icon_map.sh`). Empty workspaces show a faint ghost icon for their intended purpose.

### Required fonts (manual install)

- **SF Pro** — [Apple Developer](https://developer.apple.com/fonts/)
- **SF Symbols** — [Apple Developer](https://developer.apple.com/sf-symbols/)
- **sketchybar-app-font** — installed automatically via Homebrew Cask

### Required tools

- **ifstat** — network speed widget. Declared in `modules/macos/base/homebrew.nix`; it is one of the few remaining Homebrew formulae because there is no nixpkgs package for it. No manual `brew install` needed.
